# E4 方法理解与交接说明

本文帮助你解释和检查实验。具体成绩与图表来自 `results/e4/report_section.md`；这里不预设 RoBERTa 一定优于其他模型。

## 你需要能说明的实验问题

E4 研究 RoBERTa 微调的学习率是否影响验证集表现，以及它的检测效果是否值得推理成本。实验内部只改变学习率；其余参数固定。与 E3 的对比则涉及模型规模、预训练方式、分词器和实现版本等多种差异，因此不能把差异归因于某一个架构设计。

## 模型如何处理文本

1. RoBERTa 的 byte-level BPE 分词器把文本转换为 token ID，加入特殊标记；最长保留 256 个 token。
2. token ID 经过词嵌入和 Transformer 编码器。注意力机制允许一个位置利用其他可见位置的信息。
3. 序列分类头读取开头位置的表示，通过全连接层、非线性和 dropout，产生正常类与攻击类的两个 logit。
4. softmax 得到两个归一化分数。我们保存类别 1 的 `score_attack`，分数越大表示模型越倾向攻击。
5. 训练使用交叉熵，更新编码器和分类头的全部可训练参数。评测时切换为 eval 模式关闭 dropout。

softmax 输出不等于现实中的恶意概率。数据来源、正常/攻击比例、标注方式和校准误差都会影响它的含义。

## 为什么分成训练 验证 测试

D1 train 用来更新权重。D1 validation 用来选学习率和 epoch。模型固定后才用 D1/D2/D3 test 衡量表现。根据测试成绩再换 checkpoint，会把测试集变成调参集，因而本实现锁定了配置和 checkpoint 哈希。

E4 在固定阈值 0.5 下比较六个候选；E6 后续使用同一个模型的验证分数选择 tF1/t5。模型选择和工作阈值选择是不同步骤。

## 三个指标如何解释

- Macro F1：正常类 F1 与攻击类 F1 的算术平均。选 checkpoint 使用此指标。
- Attack Recall：TP / (TP + FN)。攻击样本中检出多少。
- FPR：FP / (FP + TN)。正常样本中误报多少，不能用 1 − precision 代替。

D2 只有 56 条正常样本和 60 条攻击样本。一个额外误报就使 FPR 增加约 1.79 个百分点，因此小差异不能直接解释为稳定优势。D4 全部正常，只能做误报分析。

## 成本测量如何解释

batch 1 模拟逐条输入的预测。中位数代表典型耗时，P95 表示本次测量中 95% 的样本耗时不超过该值；这不是线上服务 SLA。计时包含分词、数据传输、模型前向、softmax 和返回标量，不包含加载模型。

E3 与 E4 在本机使用同一批验证样本重测。原 E3 设备与本机不同，不能直接用原 E3 延迟与本机 E4 延迟判断模型快慢。训练峰值显存、推理峰值显存、PyTorch 分配和保留内存也要分开报告。

## 遮蔽图如何解释

例子中的一个词可能对应多个 BPE token。脚本把这个词对应的 token 替换成 mask，保留位置和长度，再重新计算分数。

`delta = 原分数 − 遮蔽后分数`。正值表示遮蔽该词后攻击分数下降；负值表示分数上升。这只能说明该输入在这种改动下的局部敏感性。mask 可能产生训练时少见的文本，单词之间也有交互，因此不能说“模型做出判断的因果原因就是这个词”。六个案例来自 E2 的固定案例表，不保证它们也被 E4 错分。

## 建议亲自检查的内容

- 读 `configs/e4.json`，能解释学习率、epoch、batch、seed 和模型选择规则。
- 查看六行 tuning 表，手动核对选中行符合规则，理解为何最后一个 epoch 未必最好。
- 从预测表挑一个 FP 和一个 FN，核对文本、gold、分数和阈值。不要改动原标签。
- 任选一个解释案例，对照原分数与遮蔽分数手算 delta，并说明局限。
- 运行 `python -m experiments.e4.verify`，了解验证通过说明了什么、没有说明什么。
- 把你实际做过的修改、检查和结论记录下来；按课程要求披露 AI 的代码和写作辅助。

## 与其他成员的边界

E6 负责正式阈值、统一预测与误报区间。E5 负责最终跨来源主表。E3 的应用可复用 `predict.py`。E2 可以把这里的六案例结果用于解释讨论。不要把 E4 的 0.5 参考结果混入 E6 的 tF1/t5 主表而不标明阈值。
